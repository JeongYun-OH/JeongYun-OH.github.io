# Claude Code로 블로그 글쓰기 시간을 절반 이하로 줄이는 법 — 비개발자 마케터의 실전 파이프라인

## 1. 블로그 한 편에 몇 시간 쓰고 계신가요?

블로그 글 한 편을 완성하는 데 얼마나 걸리시나요?

주제를 잡는 데 30분, 레퍼런스를 찾는 데 또 30분. 초안을 쓰다가 막히면 예상보다 시간이 더해집니다. 목차 정하고, 제목을 고치고, 문구를 잡고 나면 어느새 세 시간이 지나 있습니다. 그리고 그 세 시간 동안 정작 '쓰는 행위'에 집중한 시간은 얼마나 됐을까요?

### 1.1 글쓰기의 어느 단계가 가장 오래 걸리는가

블로그 포스팅을 크게 나누면 보통 이렇게 됩니다.

1. **주제 선정** — 무슨 글을 쓸지 결정하기
2. **리서치** — 레퍼런스 찾고 정보 수집하기
3. **구조 잡기** — 목차와 흐름 설계하기
4. **초안 작성** — 실제로 문장 쓰기
5. **다듬기** — 퇴고·교정·제목 확정
6. **발행 준비** — 이미지, 메타 설명, 태그 등

이 여섯 단계 중 시간을 가장 많이 잡아먹는 건 대부분 2번과 4번입니다. 리서치는 탭을 열 개씩 열다 보면 끝이 없고, 초안은 첫 문장에서 막히면 시작 자체가 어렵습니다.

처음에는 의욕이 넘처 시작한 글쓰기가 점점 지치고 힘이 듭니다. 매번 비슷한 과정을 처음부터 다시 합니다

AI 글쓰기 자동화가 관심을 받는 건 바로 이 문제를 해결해 주기 때문입니다. 특히 Claude Code가 주목받는 이유는, 단순히 "문장을 대신 써주는 것"을 넘어서 이 여섯 단계 전체를 하나의 흐름으로 연결할 수 있기 때문입니다.

### 1.2 Claude Code는 챗GPT·일반 Claude와 무엇이 다른가

저도 챗GPT나 Claude로 이미 글쓰기를 시도해봤지만 결과물이 어떻게 어떤 기준으로 나왔는지 확실치 않고 요청 -> 수정 -> 재요청 -> 수정 이런 작업의 반복은 오히려 그냥 내가 쓰는 게 낫겠다는 생각을 들게 합니다..

챗GPT나 Claude 같은 일반 AI 채팅 도구는 대화 창에서 질문하면 답변을 주는 방식입니다. 한 번 대화가 끝나면 맥락이 희미해지고, 파일을 직접 만들거나 여러 작업을 순서대로 실행하는 데는 한계가 있습니다. 그러니 요청 -> 수정을 반복할 수 밖에 없습니다.

**Claude Code는 다릅니다.** 

Claude Code는 명령 프롬프트, 터미널 환경에서 작동합니다. claude code의 다른 점은

- **파일을 직접 만들고 수정합니다.** 글 초안을 텍스트 파일로 저장하고, 제목을 바꾸고, 버전을 관리합니다.
- **여러 단계를 순서대로 실행합니다.** "리서치하고 → 목차 잡고 → 초안 써"라는 흐름을 한 번에 지시할 수 있습니다.
- **기억이 유지됩니다.** 이전 작업 맥락을 파일로 저장해두면 다음 번에도 같은 스타일로 작업합니다.

비유하자면, 챗GPT는 질문에 즉석에서 답해주는 카페 직원이고, Claude Code는 내 컴퓨터 안에서 지시를 받아 실제로 파일을 만들고 작업을 완수하는 전문 비서입니다.

다만, 주의할 점이 있습니다.
Claude Code 기본 설치만으로는 "그냥 쓸 만한" 수준의 블로그 글이 나옵니다. 퀄리티 높은 글이 나오려면 추가 설정이 필요합니다. 구체적으로는 **Skills**(역할별 작업 지침)와 **MCP**(외부 도구와 연결하는 플러그인 같은 것)를 붙여야 합니다.

Skills는 "SEO 글쓰기 전문가처럼 행동해"라는 역할 지침을 파일로 만들어 Claude Code에 연결하는 방식입니다. MCP는 Claude Code가 구글 검색, 노션, 워드프레스 같은 외부 서비스와 실제로 연동할 수 있게 해주는 연결 장치입니다.

이 설정들이 있어야 "리서치도 하고 → 내 톤으로 쓰고 → 노션에 저장까지"가 자동으로 돌아가는 파이프라인이 됩니다. H2 3에서 이 파이프라인 전체를 보여드립니다.

## 2. 비개발자도 쓸 수 있다 — Claude Code 첫 실행까지

"터미널이라고요? 저는 코딩 한 줄도 모르는데요."

이 반응이 자연스럽습니다. 터미널은 개발자 전용 도구라는 인식이 강하고, 처음 화면을 보면 검은 배경에 깜빡이는 커서가 전부라 위압적입니다.

그런데 Claude Code를 쓰는 데 코딩 실력은 필요 없습니다. 이유는 간단합니다. 터미널에 직접 코드를 입력하는 게 아니라, **프롬프트(자연어)로 하고 싶은 것을 말하면** Claude Code가 알아서 처리하기 때문입니다.

### 2.1 설치·설정 5분 안에 끝내기

Claude Code는 Anthropic이 만든 Claude 모델 기반의 터미널 도구입니다. 설치는 세 단계입니다.

**1단계: Node.js 설치**

Node.js는 Claude Code가 실행되기 위해 필요한 기반 프로그램입니다. 크롬을 설치하는 것과 비슷하다고 생각하면 됩니다.

- [nodejs.org](https://nodejs.org) 접속 → "LTS" 버전 다운로드 → 설치 파일 실행

**2단계: Claude Code 설치**

터미널을 열고(맥: Spotlight에서 "Terminal" 검색, 윈도우: 시작 메뉴에서 "PowerShell" 검색) 아래 명령어를 그대로 붙여넣습니다.

```
npm install -g @anthropic-ai/claude-code
```

엔터를 누르면 자동으로 설치됩니다.

**3단계: API 키 연결**

Claude Code는 Anthropic의 API를 통해 작동합니다. API는 Claude Code가 AI 기능을 쓰기 위한 열쇠 같은 것입니다.

- [console.anthropic.com](https://console.anthropic.com) 가입 → API Keys → "Create Key" → 키 복사
- 터미널에서 `claude` 입력 후 엔터 → 안내에 따라 키 붙여넣기

이 세 단계가 끝나면 터미널에서 `claude`라고 입력했을 때 대화 창이 열립니다. 설치 완료입니다.

> ⚠️ API 사용에는 소액의 비용이 발생합니다. Anthropic 콘솔에서 사용량을 확인할 수 있으며, 블로그 글 한 편 기준 통상 수백 원 수준입니다. 정확한 요금은 [Anthropic 요금 페이지](https://www.anthropic.com/pricing)에서 확인하세요.

### 2.2 코드를 몰라도 되는 이유

Claude Code와의 대화는 영어나 한국어로 자연스럽게 합니다. "이 주제로 블로그 글 목차 잡아줘"라고 입력하면 됩니다.

터미널이 낯설게 느껴지는 건 처음 한두 번뿐입니다. 실제로 Claude Code를 쓸 때 입력하는 건 명령어가 아니라 문장입니다.

다만, 처음 설정 단계에서 Skills와 MCP를 연결하는 작업은 파일을 하나 만들고 경로를 지정하는 과정이 포함됩니다. 이 부분이 처음에는 가장 막히는 지점입니다. 이 설정을 한 번만 해두면 이후에는 "글 써줘"라는 말 한 마디로 파이프라인이 돌아갑니다.

## 3. 주제 선정부터 발행까지 — 6단계 파이프라인 전체 공개

이제 실제 파이프라인입니다.

저는 마케터로 일하면서 Claude Code로 블로그 자동화를 직접 구축해봤습니다. 아래는 그 과정에서 정착된 6단계 흐름입니다.

### 3.1 파이프라인 흐름도

```
[주제 입력]
    ↓
[리서치 에이전트]  ←── MCP: 웹 검색, 노션
    ↓
[브리프 생성]      ←── Skills: SEO 분석 지침
    ↓
[초안 작성]        ←── Skills: 글쓰기 역할 지침 (6개 에이전트)
    ↓
[검토·편집]        ←── 운영자 직접 개입
    ↓
[발행 준비]        ←── MCP: 워드프레스 또는 노션
```

각 단계마다 역할이 다른 에이전트(Claude Code 안에서 특정 지침을 따르는 세팅)가 맡아서 처리합니다. 단일 대화창에서 모든 걸 처리하는 것과 달리, 역할을 나눠야 각 단계의 퀄리티가 올라갑니다.

### 3.2 각 단계별 프롬프트 예시

**1단계 — 주제 선정**

```
이번 주에 쓸 블로그 주제 후보 5개를 제안해줘.
대상 독자는 AI 도구에 관심 있는 비개발자 마케터야.
검색량이 있으면서 경쟁이 낮은 주제 위주로.
```

**2단계 — 리서치**

MCP로 웹 검색이 연결돼 있으면 Claude Code가 직접 검색하고 결과를 정리합니다.

```
"Claude Code 활용법"을 주제로 블로그 리서치를 해줘.
현재 상위 노출 글들의 공통점과 빠진 내용을 분석하고,
독자가 가장 궁금해할 질문 5개를 뽑아줘.
```

**3단계 — 구조 설계 (브리프·목차)**

```
리서치 결과를 바탕으로 블로그 글 목차를 만들어줘.
H2 5개, 각 H2 아래 H3 2~3개 구조로.
도입은 독자의 경험에서 시작하고, 마무리는 행동 유도로 끝내줘.
```

**4단계 — 초안 작성**

여기서 Skills의 역할이 가장 크게 드러납니다. 글쓰기 역할 지침 파일(예: `writing-rules.md`)이 연결돼 있으면 Claude Code는 그 지침대로 씁니다.

```
위 목차를 기반으로 블로그 초안을 작성해줘.
writing-rules.md의 톤 가이드를 따르고,
각 H2마다 비유 한 번, 예시 한 번씩 넣어줘.
```

**5단계 — 검토·편집**

초안이 나오면 제가 직접 읽고 고칩니다. AI가 놓친 사실 관계, 내 경험에서 나오는 디테일, 독자에게 더 와닿는 표현 — 이 세 가지를 중심으로 손봅니다. 전체를 다시 쓰는 게 아니라 **최소 편집**입니다.

**6단계 — 발행 준비**

```
이 글의 SEO 메타 설명을 150자 이내로 써줘.
핵심 키워드는 "Claude Code 활용법"과 "AI 블로그 포스팅"이야.
```

MCP로 노션이나 워드프레스가 연결돼 있으면 저장까지 자동으로 됩니다.

### 3.3 Before/After: 3시간 → 30분 실측 비교

파이프라인을 구축하기 전과 후를 비교하면 이렇습니다.

| 단계 | 파이프라인 전 | 파이프라인 후 |
|---|---|---|
| 주제 선정 | 30~60분 | 5분 (AI 제안 검토) |
| 리서치 | 40~60분 | 5~10분 (AI 실행 + 검토) |
| 목차 설계 | 20~30분 | 5분 |
| 초안 작성 | 60~90분 | 10~15분 (AI 실행) |
| 편집·퇴고 | 30~40분 | 30~40분 |
| 발행 준비 | 10~20분 | 5분 |
| **합계** | **약 3~4시간** | **약 45~60분** |

편집 시간은 줄지 않습니다. 오히려 이 단계가 핵심입니다. AI가 만든 초안을 내 목소리로 만드는 시간이기 때문입니다.

시간이 줄어드는 구간은 리서치와 초안 작성입니다. 이 두 단계의 시간을 줄여줘 초반 진입의 허들을 낮춰주고 완벽하게 조사하고 글을 써야 한다는 강박에서 벗어나게 됩니다. 

사실 내가 a-z 까지 직접하는 건 시간이 오래 걸리지만, 내 아이디어를 가지고 누군가 뼈대를 만들어주면, 그걸 수정하고 개선해 나가는 건 훨씬 쉽다고 생각합니다. 

 파이프라인 구축 자체에는 시간이 걸렸습니다. Skills 파일을 만들고, MCP 연결을 설정하고, 프롬프트를 다듬는 과정이 처음에는 두세 시간이 걸렸습니다. 그러나 한 번 만들어두면 이후 모든 글에서 그 시간을 되돌려받습니다. 투자라고 보면 됩니다.

## 4. 내 목소리를 잃지 않는 법 — 톤앤매너 유지 전략

AI 글쓰기에서 가장 신경 써야 하는 부분입니다.

"AI가 쓴 글 같아 보이지 않을까요?" "내가 쓴 글이라고 할 수 있을까?"

AI가 쓴 초안은 문법도 맞고 구조도 있지만, 읽고 나면 어딘가 밋밋하고 어색합니다. 매끄럽지만 개성이 없는 글. 이게 AI 초안의 기본값입니다.

그런데 이 문제는 '어떻게 쓰라고 지시하느냐'하는지와 내가 점검하는 과정을 거치면 해결됩니다. 
아래는 AI가 쓴 초안을 최대한 나스럽게 바꾸는 방법입니다.

### 4.1 페르소나 프롬프트 설계법

Skills 파일, 즉 Claude Code에 연결할 글쓰기 지침 파일을 잘 만드는 것이 핵심입니다.

페르소나 프롬프트는 "이런 사람처럼 써줘"가 아닙니다. **"이런 상황에서 이런 독자에게 이런 방식으로 설명해줘"**가 훨씬 효과적입니다.

좋은 페르소나 지침 파일에 들어가야 할 것들:

**1. 독자 설정**
```
독자: AI 도구에 관심 있는 비개발자. 챗GPT는 써봤지만
Claude Code는 처음 접하는 사람. 기술 용어에 익숙하지 않다.
```

**2. 톤 설정**
```
말투: 전문가 친구처럼. 가르치는 말투가 아니라 먼저 써본 사람이
카페에서 알려주듯. 존댓말 기본, "~합니다" 단정형 유지.
(나의 글쓰기, 말투 특징 등을 정리해서 추가하면 좋습니다.)
```

**3. 금지 패턴**
```
- "이 글에서는 ~을 다룹니다" 식의 선언 금지
- "결론적으로", "정리하면" 식의 마무리 금지
- "강력한", "혁신적인" 같은 막연한 형용사 금지
- 새 개념 등장 시 반드시 비유 한 번 포함
```

**4. 구조 패턴**
```
도입: 독자의 경험 장면으로 시작 → 질문으로 끝
각 H2: 핵심 주장 먼저, 근거 뒤에
마무리: 요약 없이 핵심 메시지 하나 + 다음 행동 권유
```

이 지침 파일이 writing-rules.md 같은 이름으로 저장돼 있으면, 초안을 쓸 때마다 Claude Code가 참고합니다.

### 4.2 AI 초안을 나답게 다듬는 최소 편집 루틴

최소 편집은 전면 재작성이 아닙니다. 다음 세 가지만 해도 글의 체감이 달라집니다.

**1. 첫 문장과 마지막 문장을 직접 쓴다**

도입 첫 문장과 글 전체의 마지막 문장은 내가 씁니다. 이 두 문장이 글의 인상을 결정합니다. AI는 무난한 문장을 내지만, 글의 첫인상과 여운은 사람이 만드는 게 훨씬 낫습니다.

**2. "그래서 뭐가 좋다는 거야?" 자리에 내 의견을 넣는다**

AI 초안에서 "이 기능은 유용합니다"라고 쓰인 자리를 찾아서, 내가 실제로 어떤 상황에서 유용하다고 느꼈는지 구체적인 상황으로 바꿉니다. 추상적 평가 → 구체적 맥락. 이것 하나만으로 글이 살아납니다.

**3. AI가 고른 단어 중 내가 안 쓰는 단어를 바꾼다**

"활용", "구현", "최적화" 같은 단어는 AI가 즐겨 쓰지만 내가 평소 말할 때 잘 안 쓰는 단어입니다. 이런 단어들을 내가 실제 쓰는 표현으로 바꿉니다. "활용" → "써서", "구현" → "만들어서", "최적화" → "더 낫게 다듬어서".

이 세 가지에 10~20분을 쓰면, 읽는 사람이 "AI가 쓴 것 같다"고 느끼는 포인트 대부분이 사라집니다.

**4. AI가 쓴 글을 처음부터 정독해본다.**
정독하고 내가 어색하다고 느끼는 부분을 직접 수정하고 개선합니다.
AI에게 일부 작업을 맡긴 것이고 최종 검토와 글 발행은 내가 직접해야 합니다.

## 5. 지금 바로 시작하기 — 마무리 및 다음 단계

블로그 글쓰기에서 시간이 사라지는 건 글 실력이 부족해서가 아닙니다. 매번 처음부터 시작하기 때문입니다. 주제를 다시 잡고, 레퍼런스를 다시 찾고, 구조를 다시 설계하는 것에서 시간이 걸리고 번거롭기 때문에 어려운 것입니다.

Claude Code로 한 번 파이프라인을 만들어두면, 이 반복 작업의 대부분을 건너뜁니다. 비개발자 마케터 관점에서 봤을 때, Claude Code를 쓰기 시작한 뒤 달라진 건 글쓰기 실력이 아니라 **글쓰기에 쓰는 시간의 구조**입니다. 리서치와 초안에 사라지던 시간이 편집과 내 경험을 넣는 데 쓰이게 됩니다.

다음 단계로 권하는 것은 하나입니다.

**오늘 Claude Code를 설치하고, 다음 글 하나의 목차만 짜봅니다.**

완성된 글을 목표로 하면 부담이 크지만, 목차 하나는 15분이면 됩니다. 그 결과물을 보고 나서 '이걸로 할 수 있겠다'는 판단을 내려도 늦지 않습니다.

Skills와 MCP 설정, 페르소나 프롬프트 파일 구성은 그 다음입니다. 순서대로 하나씩 붙이면 됩니다.
