## 1. 기본 쿼리문 구조 (Basic Syntax)

SQL을 작성할 때는 정해진 순서를 지켜야 에러가 나지 않음. 가장 기본이 되는 구조와 작성 순서.

* **SELECT**: (필수) 가져올 컬럼 선택 (`*`은 전체 컬럼)
* **FROM**: (필수) 데이터를 가져올 위치 (`프로젝트.데이터셋.테이블`)
* **WHERE**: (옵션) **집계 전** 원본 데이터 필터링
* **GROUP BY**: (옵션) 특정 컬럼 기준으로 그룹화 (집계 함수 사용 시 필수)
* **HAVING**: (옵션) **집계 후** 결과에 대한 필터링 조건
* **ORDER BY**: (옵션) 정렬 (`ASC`: 오름차순, `DESC`: 내림차순)
* **LIMIT**: (옵션) 출력할 행 개수 제한

> **Note:** 컬럼이나 테이블에 별칭을 붙일 때는 `AS`를 사용한다.

## 2. WHERE 절과 데이터 타입

필터링 조건을 걸 때 데이터 타입에 따른 **따옴표("")** 사용 규칙을 정확히 지켜야 한다.

**문법**

```sql
WHERE 컬럼명 연산자 값
-- 연산자: AND, OR, IN, LIKE 등
```

✅ 데이터 타입별 규칙

내가 가장 많이 실수하는 부분이다. 날짜도 문자열처럼 따옴표가 필수다. <br>
1. STRING (문자): 따옴표 필수 ("apple", 'apple') <br>
2. DATE/TIMESTAMP (날짜): 따옴표 필수 ("2023-01-01")
    - 실수 주의: 따옴표 없이 `2025-01-01`로 적으면 `2023 - 1 - 1 = 2025`이라는 숫자 연산으로 인식됨.

3. INT/FLOAT (숫자): 따옴표 없음 (100, 3.5) <BR>
<BR>

**예시 코드**

```
SELECT *
FROM `dataset.logs`
WHERE
  category LIKE "%food%"        -- 문자: 따옴표 O, %는 와일드카드
  AND user_id = 12345           -- 숫자: 따옴표 X
  AND event_date >= "2024-01-01" -- 날짜: 따옴표 O (절대 잊지 말기)
```

## 3. JOIN (데이터 연결)
두 테이블을 공통된 Key 값으로 연결할 때 사용. <br>
데이터 누락을 방지하기 위해 기본적으로 LEFT JOIN을 우선 고려하자.

**기본 구조**
- LEFT JOIN: 왼쪽 테이블(기준)의 데이터는 모두 살리고, 오른쪽 테이블에 매칭되는 정보만 붙인다.

```
SELECT 
  a.user_id, 
  b.order_amount
FROM `dataset.users` AS a        -- 기준 테이블 (별칭 a)
LEFT JOIN `dataset.orders` AS b  -- 붙일 테이블 (별칭 b)
ON a.user_id = b.user_id         -- 연결 고리 (Key)
```

## 4. 서브쿼리 (Subquery)
쿼리 안에 들어있는 또 다른 쿼리. 소괄호 ()로 감싸야 한다.

**활용 상황**
1. 데이터를 미리 가공(전처리)해서 가상의 테이블을 만들 때
2. WHERE 절 등에서 동적으로 값을 비교해야 할 때

```
SELECT * FROM (
  -- [전처리] 가상의 테이블 생성
  SELECT user_id, SUM(amount) as total
  FROM dataset.orders
  GROUP BY user_id
) 
WHERE total > 10000 -- dataset.orders 테이블에서 가공된 결과(total)를 기준으로 다시 필터링

```

## 5. WITH 문 (CTE)
서브쿼리가 복잡해질 때, 이를 맨 위로 빼서 **'임시 테이블'** 처럼 정의하는 방식. 쿼리가 길어지면(대략 10줄 이상) 가독성을 위해 무조건 WITH 문을 쓰는 습관을 들이자.

**문법**<BR>
`WITH 별칭 AS ( 쿼리 )` 형태

**예시 코드**
```
WITH base_data AS ( 
  -- 1. base_data라는 이름으로 미리 정의
  SELECT user_id, event_name 
  FROM `dataset.events` 
  WHERE event_date = "2024-01-01"
)

-- 2. 실제 쿼리에서는 정의한 이름만 호출
SELECT * FROM base_data 
WHERE event_name = 'purchase'
```

## Summary (기억할 것)
- 날짜(Date)도 문자처럼 따옴표("")를 쓴다. (숫자 연산되지 않도록 주의)
- 데이터 유실 방지를 위해 LEFT JOIN을 기본으로 사용한다.
- 쿼리 로직이 복잡해지면 WITH 문으로 분리하여 가독성을 높인다.

## 참고 (쿼리 실행 순서)

| 실행 순서 | SQL 절 | 역할 |
| :---: | :---: | :--- |
| **1** | **FROM** | 어떤 테이블(또는 조인 결과)에서 데이터를 가져올지 결정 |
| **2** | **WHERE** | 각 행(Row) 단위로 조건 필터링 (**집계 전**) |
| **3** | **GROUP BY** | 남은 행들을 특정 기준으로 그룹핑 |
| **4** | **HAVING** | 그룹핑된 결과에 대해 조건 필터링 (**집계 후**) |
| **5** | **SELECT** | 최종적으로 보여줄 컬럼 선택 및 계산 |
| **6** | **ORDER BY** | 결과 데이터 정렬 |
| **7** | **LIMIT** | 출력할 행의 개수 제한 |

- WHERE이 GROUP BY보다 먼저 실행되기 때문에 GROUP BY로 그룹화된 컬럼은 WHERE로 필터가 불가능
- FROM 이 SELECT보다 먼저 진행되기 때문에 SELECT에서 별칭으로 붙은 컬럼을 WHERE, GROUP BY, ORDER BY 불가능 
    - 별칭 붙은 컬럼을 이용하고 싶다면 `서브쿼리` 또는 `WITH`을 활용해야 함.

## 코딩 테스트 오답 및 자주 쓰는 쿼리

**중복 제거**
- DISTINCT : 중복 제거해서 컬럼을 가져옴, 고유의 수를 셀 때 COUNT와 자주 사용.
```
SELECT DISTINCT city FROM customers;
--- 컬럼의 고유한 수를 파악할 때 COUNT와 함께 활용


# 1. 고유한 사용자 수 파악
SELECT COUNT(DISTINCT user_id) AS unique_users
FROM web_log
WHERE event_date BETWEEN '2025-01-01' AND '2025-01-31';

# 2. 상품 구매자 수 (Unique Buyers)
SELECT COUNT(DISTINCT buyer_id) AS unique_buyers
FROM orders
WHERE order_date >= '2025-01-01';


```

**날짜 관련 함수**
- DATE_TRUNC(날짜컬럼, 단위)
    - `MONTH`(월), `WEEK`(주), `YEAR`(년)
    - **첫 번째 날짜**로 통일

- TIMESTAMP_DIFF(종료시간, 시작시간, 단위)
    - 단위: SECOND(초), MINUTE(분), HOUR(시)

- DATE_DIFF(종료일, 시작일, 단위)
    - (최신 날짜, 과거 날짜) 순서로 넣어야 양수 나옴

- FORMAT_DATE(포맷문자열, 날짜 컬럼)
    - 날짜 포맷 변환 (YYYY-MM-DD)

<BR>

**날짜 포맷 기호와 와일드 카드**

1. **함수 안에서(`FORMAT_DATE`) 쓸 때:** : "날짜를 이런 모양으로 바꿔줘" (서식 지정)
2. **조건절 안에서(`LIKE`) 쓸 때:** : "이걸로 시작하는 거 다 찾아줘" (검색 패턴)

-  **날짜 서식 (Format String)**<BR>
`FORMAT_DATE` 같은 함수 안에서 따옴표(`''`) 안에 들어가는 `%Y`, `%m`, `%d`는 **날짜의 부품**을 의미한다.

    - **`%Y`**: 년도 4자리 (Year, 예: 2025)
    - **`%m`**: 월 2자리 (Month, 예: 12)
    - **`%d`**: 일 2자리 (Day, 예: 28)
<BR><BR>

| 코드 | 의미 | 예시 결과 (2024년 5월 20일 기준) | 
| :--- | :--- | :--- | 
| **`'%Y-%m-%d'`** | 년-월-일 (하이픈 포함) | `2025-12-28` |
| **`'%Y%m%d'`** | 년월일 (하이픈 없음) | `20251228` |
| **`'%Y년 %m월'`** | 한글 포함 | `2025년 12월` |
<BR>

```
SELECT FORMAT_DATE('%Y-%m-%d', CURRENT_DATE()) -- 결과: "2025-12-28"
SELECT FORMAT_DATE('%Y%m%d', CURRENT_DATE())   -- 결과: "20251228"
```


- 검색 와일드카드 (Wildcard Character)<BR>
`LIKE` 연산자나 테이블 이름 뒤에 붙는 %는 **"무엇이든(Anything)"**이라는 뜻의 검색 기호다.
202405%: "202405"로 시작하고, 뒤에는 뭐가 오든 상관없음
    - 찾아지는 것들: `20240501`, `20240520`, `20240531`, `202405abc...`

```
-- 예: 2024년 5월 테이블만 싹 다 긁어오고 싶을 때
SELECT *
FROM `dataset.events_*`
WHERE _TABLE_SUFFIX LIKE '202405%' -- 202405 뒤에 01이 오든 31이 오든 다 OK

-- 참고) _TABLE_SUFFIX는 와일드카드 테이블(*)을 조회할 때, 와일드카드 문자(*) 위치에 매칭되는 테이블 이름의 일부를 저장하는 가상 컬럼
```
